# 話題ジェネレーター

配信者が一人で話すときの「話し相手」になるツールです。話した内容に沿って次の話題を提案し、発言だけをもとにした要約メモを作ります。ログ（要約・文字起こし）とネタ帳は端末内に保存します。

**公開版: https://son-jo-sokora.github.io/topic-generator/** （Chrome推奨。各自のAIのAPIキー（Anthropic・OpenAI・Google Gemini のいずれか）か、手元のLLMが必要です）

- ファイルは **`topic-generator.html` の1つだけ**です。ビルドや外部ライブラリは要りません。
- Claude内（artifact）と単体のウェブページのどちらでも動きます。`window.claude` があるかどうかで自動的に切り替えます。
  - Claude内：AIは利用者のClaudeアカウント、保存はClaudeのデータベース
  - 単体：AIは利用者自身のAPIキー（Anthropic・OpenAI・Google Gemini、またはOpenAI互換の手元のLLM）、保存はブラウザのIndexedDB
- AI・保存・ファイル書き出し・音声認識は、スクリプト内の「接続口（アダプター）」で差し替えられるようにしてあります（`initStore`、`start` を参照）。

## 画面の構成

- **上部の帯**：マイクの開始・停止、「今すぐ話題をもらう」、状態の表示、保存の状態、AIの利用の目安。
- **左の列（設定）**：項目ごとに折りたためます（開け閉めは覚えています）。いちばん上の「機能のオン・オフ」で、使う機能を選べます。
- **中央の列（配信中に見るところ）**：進行表のバー、沈黙の知らせ、話題のカード、視聴者のコメント。
- **右の列（タブ）**：メモ（要約・文字起こし・補正・表示するセッション）／まとめ／ネタ帳／準備（進行表・配信前の準備）／過去（検索・バックアップ）。
- スマートフォンの幅では、話題のカードがいちばん上に来ます。

## 機能のオン・オフ

「機能のオン・オフ」で切った機能は、画面から消え、AIの呼び出しや指示文への反映も止まります（例：要約メモを切ると要約のAI呼び出しをしない、ネタ帳や時事ネタを切ると話題の指示文に入れない）。設定はこのブラウザに保存され、バックアップにも含まれます。マイク・文字起こし・保存・AIの接続はいつも使えます。

- 既定でオン：話題の提案、要約メモ、ネタ帳、時事ネタ、沈黙の知らせ、進行表・タイマー、配信前の準備、配信のまとめ、誤変換の補正、手元のWhisper、利用料の表示、過去の配信を探す、バックアップと移行
- 既定でオフ（外部の準備が要るもの）：視聴者のコメント、OBSに表示

## 使い方

1. 公開版を開き、「AIの接続」で提供元を選んで、APIキーとモデル名を入れます（Anthropicは既定で `claude-haiku-5-5`）。「このブラウザに保存する」にチェックを入れない限り、キーは保存されません。
2. 必要なら「あなたの関心・背景」と「時事ネタの材料」を書きます。どちらも空欄で使えます。書いた内容はこのブラウザに保存されます。
3. 「マイクを開始」を押して話します。マイクを使わずに試すときは、下の入力欄に文字を入れてEnterを押します。

## 主な機能と動き

| 機能 | 動き |
| --- | --- |
| 話題の提案 | 発言が止まって2.5秒後に3〜5個。話し続けていても、最初の発言から20秒以内に出す。自動では最短10秒おき。「今すぐ話題をもらう」で手動でも出せる |
| 要約メモ | 配信者の発言だけをもとに、話題とは別のAI呼び出しで作る。発言の3秒後から、最短15秒おきに更新 |
| 文字起こし | 要約と並べて見られる。各行の先頭に話し始めからの経過時間（例 `[12:34]`）が付く。「コピー」「ダウンロード（.md）」で書き出せる |
| 配信のまとめ | ボタン1つで、タイトル案・概要欄・チャプター・切り抜き候補・X（旧Twitter）の振り返り投稿を作る。項目ごとにコピーでき、セッションと一緒に保存・書き出しされる。過去のセッションでも作れる。動画の開始が話し始めより早いときは「チャプターの時刻をずらす」で合わせる（最初の 0:00 は動かさない） |
| ログの保存 | セッション単位で5秒ごとに自動保存。60,000字を超えると次のパートに分ける。過去のセッションも見られる |
| ネタ帳 | 手入力、文章・Xのアーカイブ（tweets.js）からの取り込み、要約からの抽出。固定・除外・削除ができ、話題の提案に使われる |
| 時事ネタ | 材料欄に書いた見出しだけを事実として、話題に1〜2個混ぜる。「ニュースの見出しを取ってくる」で、手元のサーバー経由で、自分で指定したRSSの見出しを入れられる（既定の取得元は持たない） |
| 配信スタイル | 雑談・ゲーム実況・作業配信・ラジオ（複数人）・学び/解説から選び、話題の出し方を変える |
| 沈黙の知らせ | マイク使用中に15/30/60秒黙ると、知らせを出して最新の話題を目立たせ、新しい話題を頼む（最短10秒おきの制限は守る） |
| 進行表・タイマー | 「名前 分」を1行ずつ書いて「開始」。今のコーナー・残り時間（超過も表示）・次のコーナー・経過時間を上に出し、話題の提案もコーナーに合わせる |
| 視聴者のコメント | Twitch（キー不要、読み取りのみ）とYouTube Live（YouTube Data API のキーが必要、10秒おきに取得）から取り込む。質問らしいものに色を付け、答えていない新しい10件を話題の提案に使う。クリックで「答えた」、Shift+クリックでOBSに表示 |
| OBSに表示 | お題・進行表のコーナーと残り時間・コメントを、手元のサーバー経由でOBSのブラウザソース（`http://127.0.0.1:8790/overlay`）に出す。話題カードのダブルクリックでお題にできる |
| 配信前の準備 | テーマと長さから、コーナーの流れ・オープニングの一言・話題の候補・締めの一言を作る。進行表やネタ帳にそのまま入れられる |
| 誤変換の補正 | 文字起こしを、行と時刻はそのままに、同じ読みの別の字などだけAIが直す（約3,000字ずつ）。用語集として「認識させたい語」・ネタ帳・関心欄を使う。「補正前に戻す」で戻せる |
| 利用料の表示 | このセッションのAI呼び出し回数とトークン数を表示。料金（100万トークンあたり）を入れると金額の目安も出す（Claude内では回数のみ） |
| 過去の配信を探す | 保存した全セッションの文字起こし・要約・まとめから言葉を探し、クリックでその回を開く |
| バックアップと移行 | ログ・ネタ帳・設定をまとめて .json に書き出し、別のブラウザやPCで読み込む（APIキーは含めない） |

AIが使えないとき（キーが空、キーが無効、利用上限）は、**マイクと文字起こしは止めず、話題と要約だけを一時停止**します。キーを入れ直すか「今すぐ話題をもらう」を押すと再開します。画面の表示欄（左の欄の下）には、APIが返したエラー文（例: `HTTP 400: model: ... not found`）がそのまま出ます。

## 音声認識の選び方

「音声認識」欄で選びます。

- **ブラウザの音声認識（Chrome）**：準備が要りません。音声はブラウザの機能（ChromeではGoogleのサーバー）で文字にされます。
- **手元のWhisper**：このPCのNVIDIA製GPUで文字にします。音声はPCの外に出ません。次の節の準備が必要です。サーバーにつながらないときは、自動でブラウザの音声認識に切り替わります。

### 手元のWhisperの準備

[faster-whisper](https://github.com/SYSTRAN/faster-whisper) と日本語向けのモデル [kotoba-whisper](https://huggingface.co/kotoba-tech/kotoba-whisper-v2.0-faster) を、`local-asr/` の小さなサーバーで動かします。

- 必要なもの：Windows、Python 3.12、NVIDIA製GPU（動作確認はGeForce RTX 3060 Ti、8GB）
- 初回は、部品（約2GB）とモデル（約1.5GB）のダウンロードに数分かかります。2回目以降の起動は10秒ほどです。

1. `local-asr/start.bat` をダブルクリックします。「準備できました」と出たら起動完了です。この窓は開いたままにします。
2. ページの「音声認識」で「手元のWhisper」を選び、「マイクを開始」を押します。表示が「聞いています… / 手元のWhisper」になれば動いています。
3. 公開版（github.io）から使うと、Chromeが「ローカルネットワーク上のデバイスへのアクセス」を許可するか聞いてくることがあります。その場合は許可してください。

補足:

- 話の切れ目（0.7秒ほど黙ったところ、または15秒続いたところ）で音声を区切って送ります。
- サーバーは `127.0.0.1:8790` で待ち受け、公開版とローカル（127.0.0.1 / localhost の 8000・8010番）のページからの呼び出しだけを受け付けます。変えるときは `start.bat --port 番号` や `--allow-origin URL` を使い、ページの「手元のサーバー（local-asr）のURL」も合わせてください。
- 同じサーバーが、OBS表示（`/overlay`）とニュースの見出しの取得（`/news`）も受け持ちます。文字起こしが不要なら `start.bat --no-asr` で起動すると、モデルを読み込まずにすぐ使えます。
- GPUがない場合は `start.bat --device cpu` で動かせますが、遅くなります。
- 「認識させたい語」は Whisper の hotwords として渡します。効果は限定的です（下の「確認状況」を参照）。

## 保存されるデータ

| データ | 保存先 |
| --- | --- |
| セッションのログ（要約・文字起こし・まとめ・取り込んだコメント最大300件・AIの利用回数）、ネタ帳 | このブラウザのIndexedDB（Claude内ではClaudeのデータベース） |
| 関心・背景、時事ネタの材料、音声認識の設定 | このブラウザのlocalStorage |
| APIキー、モデル名 | 「このブラウザに保存する」を選んだときだけlocalStorage |

公開版とローカル（127.0.0.1）は別のサイトとして扱われるため、保存した内容は引き継がれません。

## 開発

### 手元で開く

マイク（Web Speech API）は `file://` では動かないことがあるため、ローカルのサーバーで配信して開きます。

```bash
npm run serve
```

Chromeで http://127.0.0.1:8000/topic-generator.html を開きます。

### テスト

Playwright（Chromium）で、AIの提供元・音声認識・Twitch/YouTube・手元のサーバーを模擬して動かします。実際のAPIやマイクには接続しません（手元のサーバーのテストだけは、本物の `local-asr/server.py` を `--no-asr` で起動します）。全34件、約4分半です。

```bash
npm install
```

```bash
npx playwright install chromium
```

```bash
npm test
```

| ファイル | 内容 | 所要時間 |

## 確認状況（Windows + Chrome）

確認済み:

- ブラウザからAnthropic APIを直接呼べる（CORS）。ローカル・公開版のどちらでも、本物のAPIキーとモデル `claude-haiku-5-5` で話題と要約が出て、実際のマイクでも動く（利用者による確認）
- 手元のWhisper：RTX 3060 Ti で、11.5秒の音声（Windowsの読み上げ音声）を約0.6秒で文字にできる。ページからサーバーまでの通しの動作も確認。利用者が公開版から実際の声で動かした

- 2026-11-05：全機能に自動テストを用意（33件が通過、GPUのテスト1件は既定で飛ばし、直接実行して通過）。あわせて、本物のTwitchのチャットから受け取れること、本物の手元サーバー経由で実際の報道機関のRSSから見出しが取れること、GPUで日本語の読み上げ音声（6.9秒）を正しく文字にできることを確認

次の点は、模擬でしか確かめていません。
- YouTube Live の実際のチャット
- OpenAI・Gemini・手元のLLMへの実際の接続（ブラウザから直接呼べるか）
- 実際のOBSでの見え方

未確認・課題:

- 手元のWhisperでも、同じ読みの別の字を選ぶ誤り（人名や専門用語で起きやすい）が残る。「認識させたい語」（hotwords・initial_prompt）では、この例では改善しなかった。AIによる文脈での補正が候補
- 長時間配信したときの認識精度、話題・要約が出る間隔、APIの利用料
- Claude内で保存したログを、Claudeのチャットから読み取れるか
